\section{Introduction}
\label{sec:introduction}

The board drives six cold-cathode gas-discharge indicator tubes from a USB-C
Power Delivery source. Four IN-12B tubes show the hours and minutes. Two INS-1
tubes make the colon. One K155ID1 BCD decoder/driver controls each numeric
tube. The MCU commands the driver to select one of ten cathodes.

The 170~V supply powers the tube anodes. The 5~V supply powers the drivers. The
3.3~V supply powers the MCU. The USB-PD input stage supplies all three
converters. Thus, the tube and driver ratings set the requirements for each
upstream converter.

The analysis first derives the tube and driver requirements
(\cref{sec:tubes,sec:bcd-driver}). It then derives the 170~V flyback converter
(\cref{sec:hv-components,sec:hv-converter}). The next sections derive the 5~V
and 3.3~V supplies
(\cref{sec:lv-components,sec:5v-converter,sec:3v3-converter}). The last section
derives the USB-PD input stage.

\paragraph{Method.} Each parameter for a critical named component comes from a
datasheet in \texttt{docs/datasheets/}. Each parameter includes a file and page
reference. Datasheet ranges, tolerances, and test conditions remain with the
parameter. These details identify guaranteed limits, typical values, and test
values.

Parameters without a local datasheet use standard engineering practice. This
rule applies to common resistors, capacitors, and diodes. Package constraints
apply only when a critical part is available in one package. Otherwise, the
analysis applies at the schematic level.

\paragraph{Construction.} The 170~V converter, tube circuits, and driver
circuits use through-hole parts when possible. Larger parts are preferred when
multiple parts meet the requirements. The USB-PD circuit and low-voltage
supplies use surface-mount parts. The assembly supplier installs these parts.
Construction preferences do not change the derived electrical requirements.
